## Customer clarification cross-check — 7 October 2026

Read the actual PROJECT-root `Session 1 - Clarification Answers_G8.xlsx`, rather than treating the planning matrix as the customer source. Jian Yong's rows require expected attendees, duration, preferred dates, purpose and venue requirements; the minimum-information answer also names event title and primary venue/layout preferences. The implementation represents duration as an ordered start/end interval and a primary venue preference through physical/virtual/hybrid venue type; detailed layout and free-text venue needs remain captured separately. The team's C02 does not establish whether that representation is sufficient for every venue/layout preference, so PO/team confirmation of the exact matrix remains explicit. No new mandatory layout rule or lead-time rule is invented here. This clarification predates Week 7 and must be considered during the matrix review; the Week 7 changes stay in future scope.

Customer answers also support owner-only Drafts, editing/resubmitting the existing returned request, retaining actor/time/change history and no fixed Draft expiry. Same-organisation Event visibility and pagination/page size are implementation choices; neither is presented as a customer-mandated numeric rule.


Permission amendment (7 October): use `event_requests.create`, `events.view` and `event_requests.review` from the existing auth-service catalog. Empty capabilities deny before database/replay access; malformed permission payloads fail closed. This consumes the effective permissions returned by auth-service and now includes the CS-26 secondary-role union and fixed action-role boundaries. Default technical-support capabilities do not include Event view. The guarded live smoke removes/restores three synthetic grants and requires unchanged workflow counts.
