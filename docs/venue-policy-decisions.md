## Agreement boundary — 14 October 2026

Aryan accepted proposed policies 3–6 in the project discussion. Questions 1–2 remain pending customer clarification and are not implied by these decisions. Record implementation, acceptance and deployment separately.

Room headcounts represent disjoint planned allocations during simultaneous venue use. Required rooms must account for the Event expected attendance at every booked session segment. Unbooked schedule gaps may represent breaks or travel and are not inferred to require a room. Staff must validate the configured physical capacity for the selected supported layout; the existing single Venue capacity must be safe for every supported layout (there is no independent per-layout capacity matrix). The primary location never supplies a registration limit. Registration must not exceed the reviewed attendance plan; the shared Event/registration owners implement that command boundary.

Pending extension requests do not change expiry. Arrangement edits clear the request for a fresh review; a consumed extension remains consumed. A reassigned Coordinator must submit their own request. The migration backfills consumed extensions from retained VenueHoldExtended outbox history; it never shortens historical deadlines. Expiry remains effective immediately on reads; scheduled audit/notification work is CS-90, currently unassigned. Message consumers must resolve current assignment and suppress stale deadline notices after an extension, cancellation or approval.
